## 并发冲突处理

原“所有 409 静默重试三次”不再作为统一要求。当前不同操作具有不同的数据安全约束：

- [嵌稿写入](../src/route/_authenticated/_shell/business/comic-detail/upload/artwork-write.ts) 按章节串行，仅对 HTTP 409 且业务码为 8 的冲突进行最多四次重试，支持取消与指数退避。
- [审查保存](../src/route/_authenticated/reviewer/business/editor/review-http-source.ts) 遇到 409 后读取最新内容并交给冲突恢复流程。

后续任务应按具体操作确定冲突策略，保留现有行为，避免对非幂等操作统一重放请求。验收应覆盖并发更新不丢失、重试有界、取消生效、失败反馈和恢复入口；只有明确存在缺口时才改实现。

## 兼容措施及退出条件

### 历史文本作者

[编辑动作](../src/route/_authenticated/translator/business/editor/use-editor-unit-actions.ts) 仍为缺失翻译者的历史文本补入当前用户，以满足当前完整 unit payload 的服务端要求。

退出条件是后端从认证 token 确定编辑者、完成历史缺失作者的数据迁移，并更新契约快照及联动测试。删除兜底前，应验证历史文本的编辑、保存、校对、撤销和重试均不会被拒绝或错误归属。
