# 文档维护

- 遵守根目录 `AGENTS.md` 与 `CONTRIBUTING.md`；文件职责以 `repository-conventions.md` 为准。
- 新增或移动长期维护文档时更新 `README.md` 索引；根目录 README 只链接主要入口。
- 命令、路径、版本和行为描述应核对当前源码、配置及脚本，不从历史审计直接复制为现行规则。
- `swagger.json` 是前端消费的后端契约快照。同步对应后端生成文件，记录来源版本或 SHA；不手写补丁、不另建第二份快照。前端同步记录和回归测试应与契约变更一起维护。
- `../CONTEXT.md` 只维护业务术语；实现、依赖边界和运行操作分别进入对应规范或说明。
- 删除文档前检查引用、维护用途及再生成路径；有历史依据价值的记录明确状态后归档。
- 历史记录写明时间、适用版本和复现限制。不得把过去的测试、部署、操作指示或例外当作新任务的证据或授权。
- 版本发行说明放在 `release/`，历史实验放在现有 `archive/`；不为对称建立空目录。
- 文档中禁止出现凭据、私钥、主机公钥或私有基础设施地址；公开域名与非敏感部署拓扑按贡献指南维护。
- 完成后检查 Markdown/YAML 格式、本地链接和相关命令；纯文档修改不需要启动数据库、构建发布镜像或操作生产环境。
