# PopRaKo Web 1.0.0

状态：待发布。当前版本与发行说明已准备；本地合入或仓库重建不代表已经创建版本标签、
完成生产部署或发布 GitHub Release。

## 交付能力

- 团队工作区、漫画与章节管理、任务分配、成员管理和系统信箱。
- 浏览器翻译器、术语库、文本编辑、审查标注及草稿恢复。
- 漫画 ZIP 归档导出和归档漫画浏览。
- 浏览器 TAR/Zstandard 与 ZIP 工具、嵌稿上传及相关取消和失败恢复能力。

## 前后端兼容

客户端通过 `/api/v1` 契约与 PopRaKo Server 协作。前端消费的契约记录在
[OpenAPI 快照](../swagger.json)，调用侧须与交付的后端版本核对；版本号同为 `1.0.0`
不自动证明契约兼容。

当前前端快照中的后端版本为 `0.1.0`，尚未记录已核实的后端来源 SHA；它与后端当前
工作区的快照内容不同。正式交付前需核对最终后端 commit 的生成契约，再同步快照与
调用回归。快照内版本和许可证描述后端，不用前端包版本或许可证手工覆盖这些字段。

开发环境默认把 `/api` 代理到本机后端；生产和 Release 构建使用
`https://api.poprako.com/api/v1`。生产构建从 `production` environment 的
`DEPLOY_API_BASE_URL` 映射至 `VITE_API_BASE_URL`。浏览器所见配置在构建时固定，
更换 API 地址需要重新构建。

## 部署与验收

默认发布流程要求最终 `main` commit 已通过 CI 并成功部署。Release workflow 会核验
精确 SHA 的生产部署历史，再构建和打包静态站点；API 查询失败或缺少成功记录时停止发布。
任务级本地集成例外不替代这些正式发布条件。

Release 资产包含静态站点压缩包、构建使用的 pnpm lockfile、来源记录与 SHA-256 校验文件。
站点产物附带项目、字体和第三方依赖许可。配置、生产切换和回滚见
[部署说明](../frontend-deploy.md)，完整流程见[发布策略](../../RELEASE.md)。

## 已知限制与后续维护

- 历史文本缺失作者的前端兜底仍保留，退出依赖后端契约和历史数据迁移。
- 术语库导入保持 `forceMerge: false`，尚未提供强制合并交互。
- 对比度基线检测已停用，不再作为 CI 检查项；历史额度与设计例外记录已删除。
- 声明文件兼容补丁继续按固定版本与哈希校验，依赖升级前须逐项复核。

范围与退出条件见[维护待办](../maintenance-follow-ups.md)和[依赖补丁记录](../dependency-workarounds.md)。
