# 仓库文件与目录规范

本规范明确成熟仓库所需的基础文档、配置、协作模板及其职责。参考 PopRaKo Web 与
PopRaKo Server 的现有结构，检查缺项和内容质量；已有有效入口不为名称对称机械迁移。

## 根目录文件

| 文件                 | 职责                                                           |
| -------------------- | -------------------------------------------------------------- |
| `README.md`          | 面向使用者介绍产品定位、功能亮点和使用入口，仅保留少量必要链接 |
| `LICENSE`            | 项目许可证完整正文；包元数据和 README 使用相同 SPDX 标识       |
| `CHANGELOG.md`       | 按版本整理已交付或待发布变更的摘要，明确状态                   |
| `CONTRIBUTING.md`    | 分支与贡献流程、必需检查、代码规范、依赖边界及契约更新要求     |
| `RELEASE.md`         | 版本、标签、构建、部署证据、发布资产与审批规则                 |
| `SECURITY.md`        | 安全漏洞私密报告入口、受支持范围及披露规则                     |
| `SUPPORT.md`         | 缺陷、功能建议与一般使用问题的受理范围和所需信息               |
| `CODE_OF_CONDUCT.md` | 协作行为要求、维护者处置权限与私密举报原则                     |
| `AGENTS.md`          | Agent 执行约束与专项规则入口，链接已有规范而非复制全部正文     |
| `CLAUDE.md`          | 指向根目录 `AGENTS.md` 的符号链接，不维护仓库级规则副本        |
| `CONTEXT.md`         | 已确定的业务术语及歧义消除；不放实现、操作命令或待办           |
| `.gitignore`         | 排除凭据、本地状态、缓存、生成产物及不公开分发的素材           |
| `.env.example`       | 可公开的环境变量名称及非敏感示例；不放真实凭据或私有地址       |

README、LICENSE、CHANGELOG 和 CONTRIBUTING 构成项目说明与贡献入口；SECURITY、
SUPPORT 和 CODE_OF_CONDUCT 服务于公开协作。RELEASE、AGENTS、CLAUDE 和 CONTEXT
按发布、Agent 使用和领域复杂度维护，并非所有项目都必须具有相同文件。
新增根目录文件前先判断是否已有职责归属，不添加空模板或内容重复的说明文件。

前端工具链配置继续使用 `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`
和 `.node-version`；框架、TypeScript、ESLint、Prettier 和 Vitest 配置保留工具当前使用的
入口。`index.html` 是应用入口，`justfile` 是本地快捷命令，不是 CI/CD 的依赖。
后端的 Cargo、Rust、Diesel、容器和数据库配置由后端维护，不复制进前端。

## 目录职责

| 目录          | 职责与边界                                                          |
| ------------- | ------------------------------------------------------------------- |
| `src/`        | 应用入口、路由业务及共享模块，遵守贡献指南中的依赖边界              |
| `public/`     | 需要原样分发的静态资源、字体和第三方许可                            |
| `script/`     | 可重复执行的检查、维护、生成及发布脚本；沿用前端现有单数名称        |
| `linters/`    | 项目自有规范检测实现，规则与贡献指南保持一致                        |
| `.storybook/` | Storybook 配置与预览参数，正式配置不依赖本机实验素材                |
| `.github/`    | workflow、Issue 和 PR 模板；默认受理规则与根目录治理文档一致        |
| `.agents/`    | 仓库专用 skill；根目录及子目录 `AGENTS.md` 保存适用范围内的执行约束 |
| `deploy/`     | 可公开的部署配置；凭据和私有基础设施信息保留在受控环境              |
| `docs/`       | 持续维护说明、API 契约、发行说明、审计和明确标记的历史记录          |

本地 `.env`、`node_modules/`、缓存、`dist/`、`storybook-static/` 和实验素材不属于根目录
必需文件。清理规范针对 Git 跟踪内容，不据此删除开发者的本地文件或素材。

## 文档分工

详细文档由 [docs/README.md](README.md) 统一索引。新增文档时确定一个维护目的，
避免同一规则分别写进 README、贡献指南、Agent 说明和临时计划。

- README 以产品介绍与功能亮点为主，不放运行时版本、安装命令、架构、检查清单或部署流程。
- 编码与依赖规则写入 `CONTRIBUTING.md`；术语只写入 `CONTEXT.md`。
- 每个版本的能力、兼容性、部署要求和限制写入 `docs/release/<version>.md`，CHANGELOG 保留摘要。
- 操作说明链接可执行脚本，区分本地验证、构建、发布和生产部署，不把其中一个通过写成其余已完成。
- 维护待办保留问题、范围、前置条件和验收；兼容措施记录原因及退出条件，不删除仍有数据含义的 FIXME。
- 历史实验沿用 `docs/archive/`，记录时间、素材、版本和复现限制；后端可以继续使用其 `docs/history/`。
- 删除记录前核对当前引用和保留用途。历史命令、旧 SHA 与旧授权不自动适用于当前操作。

## 后端仓库结构建议

2026-10-26 比较对象是两个仓库的当前工作区，后端含正在开发和部分暂存的发布准备内容。
以下仅是后端建议，本轮未修改其文件。

| 建议                       | 可借鉴的前端做法与后端保留项                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------- |
| 补充根目录职责与文档索引   | 明确 README、CONTRIBUTING、AGENTS、RELEASE 的边界，README 补 CHANGELOG、版本说明和 SUPPORT 入口           |
| 建立术语入口               | 前端已有 `CONTEXT.md`；后端可从现有领域规范提炼已确定术语，链接具体模型规范，不把 Rust 类型分层混入术语表 |
| 统一任务例外的记录方式     | 保留后端默认 CI/审批规则，同时明确特定用户指示只覆盖该任务；本地集成、Git 历史替换与发布分开记录          |
| 收紧 PR 模板的敏感信息措辞 | 与前端贡献指南一致，禁止凭据、私钥、主机公钥和私有地址，允许已确认的公开域名与非敏感拓扑                  |
| 分开行为与安全报告渠道     | 安全漏洞继续走私密漏洞报告；行为问题需要维护者提供实际私密入口，不能编造联系方式或默认复用漏洞专用渠道    |

前端借鉴后端的独立发行说明、发布准备清单和文档维护规则；后端可借鉴前端的术语入口
及本轮整理的文档职责表。两边各自的运行时、构建配置和代码限制继续由本仓库维护。
